# CIP-0023 — Fair Min Fees (`minPoolMargin`)

> **Status:** Active 2026/04/22. Fee-layer candidate. Evaluation against V2 §2 grid. Sources in §7.

## TL;DR

- **Verdict.** Conservative standalone fee-layer instrument. **Necessary but not sufficient** for V2: its §3.1 effect is marginal unless paired with a separate `minPoolCost` reduction.
- **Instrument.** One new parameter, `minPoolMargin` (variable-fee floor), applied inside the ledger's reward calculation after `minPoolCost`. No hard fork, no re-registration.
- **Relation to CIP-0082.** Functionally absorbed by CIP-0082 stage 2 (`minPoolRate`). **Not independent options** — a coherent package picks one.

## 1. Mechanism

**Formula** (floor applied during reward calculation, not at certificate level):

$$\mu^{\text{pool,effective}}_{i} = \max\left(\mu^{\text{pool}}_{i},\ \mu^{\text{pool}}_{\text{min}}\right)$$

**Design surface.**

| Property | Value |
| --- | --- |
| New parameter | `minPoolMargin` ($\mu^{\text{pool}}_{\text{min}}$) |
| Initial value | 0 (raised later via standard Parameter Change actions) |
| `minPoolCost` status | **Unchanged.** CIP text is explicit: "this proposal does not change or reduce the existing minimum fixed pool fee." |
| Re-registration | Not required — floor applied inside ledger reward calc |
| Layer | Fee (operator/member split, post-per-pool allocation) |
| Reward curve | Untouched |
| Pledge mechanics | Untouched |

**Intent.** Attack *fee regressivity*: `minPoolCost` alone imposes a disproportionately large effective fee rate on delegators to small pools, biasing delegation toward saturated pools. A variable-fee floor lets the effective operator take scale with pool stake.

### 1.1 Worked calibration from the CIP rationale

Comparison at epoch-382 parameters (rewards 31.2 M, saturation 64 M ADA), reference delegator 100 k ADA:

| Pool stake | Current (`minPoolCost = 340`, margin ≈ 0) | Proposed (`minPoolCost = 50`, `minPoolMargin = 1.5 %`) |
| ---: | ---: | ---: |
| 2 M | 22.7 % | 4.8 % |
| 5 M | 9.1 % | 2.8 % |
| 10 M | 4.5 % | 2.2 % |
| 20 M | 2.3 % | 1.8 % |
| 30 M | 1.5 % | 1.7 % |
| 64 M (sat.) | 0.7 % | 1.6 % |

Fee-rate dispersion collapses from **32× (22.7 / 0.7)** to **3× (4.8 / 1.6)**. **Caveat.** This requires *both* a reduced `minPoolCost` and the new margin floor; the margin floor alone does not flatten the small-pool regressive burden.

## 2. Milestone coverage

| V2 milestone | Verdict | Where it bites |
| --- | --- | --- |
| §3.1 Operator viability | Indirect | Margin floor lifts take at small/mid stake where declared margin ≈ 0; no structural-floor relief without a companion `minPoolCost` reduction |
| §3.2 Pledge as signal | No effect | Fee-layer change only |
| §3.3 Delegator yield | **Direct** | Collapses fee-rate dispersion; removes fixed-cost penalty for delegating to smaller productive pools |
| §3.4 Concentration | Indirect | Behavioural rebalancing possible; no entity-level accounting |
| §4.1 Pot survival | No effect | Redistributes *within* each pool's pot |
| §4.2 Fee-gen population | No effect | — |
| §4.3 Price robustness | Partial | Margin scales with revenue (ADA-price-coupled) — but only if `minPoolCost` also drops |
| §4.4 Governability | **Yes** | First-class protocol parameter, standard Parameter Change action |

**Dependency-chain reading.** CIP-0023 is a §3.3 instrument. Its §3.1 contribution is *conditional* on a companion `minPoolCost` reduction. Treated as a pure standalone (margin floor at non-zero value, fixed fee unchanged), the §3.1 gain is small relative to the §3.3 gain.

## 3. Validation plan

Gated per [`../methodology.md`](../methodology.md).

### 3.1 G1 — Analytical properties

| Property | Claim | Status |
| --- | --- | --- |
| Monotonicity in margin | $\mu^{\text{effective}} = \max(\mu, \mu_{\min}) \geq \mu$ | Theorem |
| No effect when declared margin ≥ floor | Status quo preserved above the floor | Theorem |
| Fixed-fee interaction | Floor applied *after* `minPoolCost`; does not change the structural-floor position | Theorem |
| Price coupling | $\mu_{\min}$ is a *ratio*; `minPoolCost` remains absolute | Mixed |
| Governance surface | One scalar ($\mu_{\min}$), `minPoolCost` unchanged | Direct count |

### 3.2 G2 — Mainnet-snapshot counterfactual

Standalone (margin floor only, `minPoolCost` unchanged) vs paired with a `minPoolCost` reduction. Immediate effect on a reference delegator at 100 k ADA, epoch-382 parameters:

| Pool stake | Current (`minPoolCost = 340`, margin ≈ 0) | Paired (`minPoolCost = 50`, $\mu_{\min} = 1.5$ %) | Standalone (`minPoolCost = 340`, $\mu_{\min} = 1.5$ %) |
| ---: | ---: | ---: | ---: |
| 2 M | 22.7 % | 4.8 % | ≈ 22.7 % (dominated by fixed fee) |
| 5 M | 9.1 % | 2.8 % | ≈ 9.1 % |
| 10 M | 4.5 % | 2.2 % | ≈ 4.5 % |
| 64 M (sat.) | 0.7 % | 1.6 % | ≈ 1.6 % |

**G2 verdict.** Fee-rate dispersion collapses from **32×** to **3×** only when paired with a `minPoolCost` reduction. Standalone margin floor is ineffective against the §3.1 structural floor on subthreshold pools.

**Populations immediately affected.**

| Population | Size | Standalone effect | Paired effect |
| --- | --- | --- | --- |
| Sub-threshold pools | 116 | Unchanged | Viable once `minPoolCost` drops |
| Viable independent single-pool | 283 | Mild fee uplift | Larger fee uplift, broader mid-tier relief |
| MPO fleet entities | 85 | Margin uplift only where declared margin < floor | Same |
| CEX / IVaaS | 10 | Margin uplift only where declared margin < floor | Same |

### 3.3 G3 — Historical analogies

| Anchor | Relevance | Caveat |
| --- | --- | --- |
| Pre-Conway `minPoolCost` era (340 ADA) | Establishes the regressive-fee baseline the floor addresses | Single parameter value, not a change event |
| No prior change of the CIP-0023 type | — | CIP-0023 introduces a new parameter; reference class is empty |

### 3.4 G4 — Population best-response reasoning

*Assumptions, not predictions.*

| Population | Pre-CIP-0023 | Plausible response under $\mu_{\min} = 1.5$ % | Threatens |
| --- | --- | --- | --- |
| Operators with declared margin ≥ floor | Status quo | Unchanged | — |
| Operators with margin < floor | Earn declared margin | Earn clamped floor | — (intended: stops race-to-zero margin) |
| Sub-threshold pool operator | Below viability due to `minPoolCost` | Unchanged standalone; viable if paired | §3.1 if standalone |
| Delegator at subthreshold pool | Net yield crushed by fixed fee | Net yield improved **only** if `minPoolCost` drops | §3.3 if standalone |
| Pool-entry candidate | Deterred by fixed-fee floor | Unchanged standalone | — |

### 3.5 G5 — Governance ramp and rollback

| Stage | Action | What to measure | Rollback trigger |
| --- | --- | --- | --- |
| Activation | Introduce $\mu_{\min} = 0$ at HFC | Baseline fee-rate dispersion, subthreshold count | N/A |
| Stage 1 | $\mu_{\min} \to 1$ % | Declared-margin distribution, delegator net-yield percentiles | Declared-margin distribution unchanged *and* yield dispersion unchanged ⇒ instrument ineffective |
| Stage 2 | $\mu_{\min} \to 1.5$ % + companion `minPoolCost` reduction | As above + subthreshold count, fee-rate Gini | Subthreshold count rising |
| Stage 3 (optional) | $\mu_{\min} \to 2$ % | As above | Viable independent SPO count falling |

**Coupling note.** Without a paired `minPoolCost` reduction, Stages 1–3 are largely symbolic against §3.1.

### 3.6 G6 — Exploratory simulation (optional)

Supplementary ablations:

- $\mu_{\min} \in \{0, 1, 1.5, 2, 3\}$ % × `minPoolCost` $\in \{340, 170, 50\}$ grid — viability-rate surface.
- Delegator-behaviour sensitivity — myopic vs inertial switching models.
- Operator-response sensitivity — do operators with declared margin just above the floor lower their stated margin to the floor?

| Aspect | Path |

| Re-registration | None. Existing certificates with margin below the floor clamped inside ledger reward calc |

## 5. Interaction audit

### 5.1 Same-layer — CIP-0023 ↔ CIP-0082

CIP-0082 stage 2 removes `minPoolCost` and introduces `minPoolRate`, which is the **same margin-floor mechanism** CIP-0023 proposes. The CIP-0082 author explicitly credits CIP-0023 for the concept.

| Scenario | Outcome |
| --- | --- |
| CIP-0023 ships first | Stage 1 of CIP-0082 composes cleanly; stage 2 effectively renames and formalises `minPoolMargin` |
| CIP-0082 ships first | CIP-0023 is redundant past stage 2 |
| Both enacted as separate items | Incoherent — same instrument under two names |

**Conclusion.** CIP-0082 functionally absorbs CIP-0023.

### 5.2 Cross-layer — CIP-0023 ↔ CIP-0050 / CIP-0037

The stake-cap candidates (CIP-0050, CIP-0037) modify $\sigma^{\text{eligible}}$ *before* the reward curve; CIP-0023 applies *after* the curve. Composition is clean — sequentially ordered by construction, no precedence rule required.

### 5.3 Dependency chain

- Margin-floor-only reform leaves §3.2 untouched (pledge stays economically inert).
- Margin-floor-only reform leaves custodial-operator concentration (CEX / IVaaS) unaddressed — entity-level accounting is beyond the fee layer.
- A full V2-aligned package pairs CIP-0023 (or its successor CIP-0082 stage ≥ 2) with a stake-cap reform.

## 6. Gaps against V2

| Gap | Why |
| --- | --- |
| §3.2 direct | No pledge-layer response |
| §3.4 structural | No entity-level accounting; behavioural only |
| §4.1, §4.2 | Fee-layer change does not touch pot composition or fee-generating population |
| Standalone §3.1 | Marginal without a companion `minPoolCost` reduction |

**Role in a V2 package.** *Necessary but not sufficient.* Primary historical role: identified the margin-floor instrument that CIP-0082 later operationalises within a staged path.
