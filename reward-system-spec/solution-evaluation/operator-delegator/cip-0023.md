# CIP-0023 — Fair Min Fees (`minPoolMargin`)

> **Status:** Active 2026/04/23. Fee-layer candidate. Evaluation against V2 §2 grid via the 5-phase methodology. Sources in §7.

## TL;DR

- **Verdict.** Conservative standalone fee-layer instrument. **Necessary but not sufficient** for V2: its §3.1 effect is marginal unless paired with a separate `minPoolCost` reduction.
- **Instrument.** One new parameter, `minPoolMargin` (variable-fee floor), applied inside the ledger's reward calculation after `minPoolCost`. No hard fork, no re-registration.
- **Relation to CIP-0082.** Functionally absorbed by CIP-0082 stage 2 (`minPoolRate`). **Not independent options** — a coherent package picks one.

## 1. Mechanism

**Formula** (floor applied during reward calculation, not at certificate level):

$$\mu^{\text{pool,effective}}_{i} = \max\left(\mu^{\text{pool}}_{i},\ \mu^{\text{pool}}_{\text{min}}\right)$$

**Design surface.**

| Property | Value |
| --- | --- |
| New parameter | `minPoolMargin` ($\mu^{\text{pool}}_{\text{min}}$) |
| Initial value | 0 (raised later via standard Parameter Change actions) |
| `minPoolCost` status | **Unchanged.** CIP text is explicit: "this proposal does not change or reduce the existing minimum fixed pool fee." |
| Re-registration | Not required — floor applied inside ledger reward calc |
| Layer | Fee (operator/member split, post-per-pool allocation) |
| Reward curve | Untouched |
| Pledge mechanics | Untouched |

**Intent.** Attack *fee regressivity*: `minPoolCost` alone imposes a disproportionately large effective fee rate on delegators to small pools, biasing delegation toward saturated pools. A variable-fee floor lets the effective operator take scale with pool stake.

### 1.1 Worked calibration from the CIP rationale

Comparison at epoch-382 parameters (rewards 31.2 M, saturation 64 M ADA), reference delegator 100 k ADA:

| Pool stake | Current (`minPoolCost = 340`, margin ≈ 0) | Proposed (`minPoolCost = 50`, `minPoolMargin = 1.5 %`) |
| ---: | ---: | ---: |
| 2 M | 22.7 % | 4.8 % |
| 5 M | 9.1 % | 2.8 % |
| 10 M | 4.5 % | 2.2 % |
| 20 M | 2.3 % | 1.8 % |
| 30 M | 1.5 % | 1.7 % |
| 64 M (sat.) | 0.7 % | 1.6 % |

Fee-rate dispersion collapses from **32× (22.7 / 0.7)** to **3× (4.8 / 1.6)**. **Caveat.** This requires *both* a reduced `minPoolCost` and the new margin floor; the margin floor alone does not flatten the small-pool regressive burden.

## 2. Milestone coverage

| V2 milestone | Verdict | Where it bites |
| --- | --- | --- |
| §3.1 Operator viability | Indirect | Margin floor lifts take at small/mid stake where declared margin ≈ 0; no structural-floor relief without a companion `minPoolCost` reduction |
| §3.2 Pledge as signal | No effect | Fee-layer change only |
| §3.3 Delegator yield | **Direct** | Collapses fee-rate dispersion; removes fixed-cost penalty for delegating to smaller productive pools |
| §3.4 Concentration | Indirect | Behavioural rebalancing possible; no entity-level accounting |
| §4.1 Pot survival | No effect | Redistributes *within* each pool's pot |
| §4.2 Fee-gen population | No effect | — |
| §4.3 Price robustness | Partial | Margin scales with revenue (ADA-price-coupled) — but only if `minPoolCost` also drops |
| §4.4 Governability | **Yes** | First-class protocol parameter, standard Parameter Change action |

**Dependency-chain reading.** CIP-0023 is a §3.3 instrument. Its §3.1 contribution is *conditional* on a companion `minPoolCost` reduction. Treated as a pure standalone (margin floor at non-zero value, fixed fee unchanged), the §3.1 gain is small relative to the §3.3 gain.

## 3. Validation plan

Structured per [`../methodology.md`](../methodology.md). Five phases: claim mapping → validity of the proposal → quantification → side-effect scan → deployment contract.

### 3.1 Phase 1 — Which problems does the CIP claim to address?

CIP-0023 predates the V2 specification. No V2 sub-section is cited directly. Every mapping below is **reconstructed framing** by this evaluation, anchored in the CIP's own rationale.

| V2 problem | Claim type | Anchor in CIP text | Evaluator note |
| --- | --- | --- | --- |
| §3.1 Operator viability | Implicit | "small pools ... disproportionately large effective fee rate" | Reconstructed — CIP's focus is delegator-side; operator-viability is a derivative claim |
| §3.3 Delegator yield | Explicit (rationale core) | "remove the regressive effect of `minPoolCost` on delegators" | The CIP's headline problem |
| §3.4 Concentration | Implicit | "biasing delegation toward saturated pools" | Reconstructed — behavioural channel only |
| §4.4 Governability | Implicit | Introduces a first-class protocol parameter, standard `ParameterChange` action | Reconstructed — structural, not narratively argued |

**Unclaimed V2 sub-sections** (no explicit or implicit coverage in CIP text): §3.2 pledge, §4.1 pot survival, §4.2 fee-gen population, §4.3 price robustness. Phase 4 checks whether the mechanism touches them as side effects.

### 3.2 Phase 2 — Validity of the proposal

For each Phase 1 claim, can the margin-floor mechanism structurally satisfy the V2 sub-section's specification, independent of parameter values?

| Claim | Verdict | Why |
| --- | --- | --- |
| §3.1 Operator viability | **Contingent** | Margin floor applied *after* `minPoolCost`; standalone, the fixed-fee structural floor is untouched. Valid *only* paired with a `minPoolCost` reduction — which CIP-0023 itself declares out of scope |
| §3.3 Delegator yield | **Valid** | Margin floor directly couples to the operator/delegator split inside the reward calculation — exactly the instrument shape §3.3 requires |
| §3.4 Concentration | **Out of reach** | Entity-level accounting (custodial clusters, multi-pool entities) is beyond the fee layer. At most a behavioural nudge via delegator redistribution |
| §4.4 Governability | **Valid** | Single new scalar, standard `ParameterChange` path. Paired variant lifts governance surface to two coupled knobs |

**Dependency flagged.** §3.1 validity is contingent on a companion `minPoolCost` reduction that the CIP does not propose. Downstream phases must either carry this pairing as a baked-in assumption or drop the §3.1 claim.

**Surviving claims for Phase 3.** §3.3 (valid), §4.4 (valid), §3.1 (contingent, paired variant).

### 3.3 Phase 3 — Quantification of claimed effects

**Claim §3.3 — Delegator yield** (primary claim):

| Tool | Quantification | Trust |
| --- | --- | --- |
| Analytical properties | $\mu^{\text{effective}} = \max(\mu, \mu_{\min}) \geq \mu$; monotone in floor; $\mu_{\min}$ is a ratio (price-invariant) | High |
| Mainnet-snapshot counterfactual (epoch-382, 100 k ADA delegator, paired with `minPoolCost = 50`, $\mu_{\min} = 1.5$ %) | 2 M pool 22.7 % → 4.8 %; 5 M → 2.8 %; 10 M → 2.2 %; 64 M (sat.) 0.7 % → 1.6 %. Fee-rate dispersion **32× → 3×** | High |
| Population best-response | Operators with declared margin < floor clamped up (race-to-zero-margin stopped); delegators migrate from saturated pools toward productive small pools | Medium |
| Historical analogies | Fee-schedule updates 2020–2021 as base rate; small reference class; no direct CIP-0023-shaped precedent | Medium-low |
| Exploratory simulation | Not required — high-trust tools converge | Low |

**Convergence.** Two high-trust tools (analytical + snapshot) support the claim. Phase 3 verdict: §3.3 carried.

**Claim §3.1 — Operator viability** (contingent, paired variant):

| Tool | Quantification | Trust |
| --- | --- | --- |
| Analytical properties | Standalone: `minPoolCost` unchanged ⇒ viability line unchanged (theorem). Paired `minPoolCost: 340 → 50`: viability line shifts proportional to the fixed-fee reduction | High |
| Mainnet-snapshot counterfactual | Standalone: sub-threshold count (116) unchanged. Paired: viability-line downshift quantifiable on the diagnostic anchor — computation pending | High (standalone) / Open (paired) |
| Population best-response | Standalone: sub-threshold operators unchanged. Paired: formerly sub-threshold pools cross into viability; pool-entry deterrence reduced | Medium |
| Historical analogies | Pre-Conway 340-ADA `minPoolCost` era as baseline — single parameter value, not a change event | Medium-low |

**Verdict.** §3.1 carried analytically for the paired variant; snapshot computation open against diagnostic anchor.

**Claim §4.4 — Governability:**

| Tool | Quantification | Trust |
| --- | --- | --- |
| Analytical properties | Standalone: 1 new scalar. Paired: 2 coupled knobs (`minPoolMargin` × `minPoolCost`) — increased calibration surface | High |

**Verdict.** Trivially valid; size of governance surface flagged for Phase 4.

### 3.4 Phase 4 — Side-effect scan

**Off-target V2 effects** (walk the V2 sub-sections *not* claimed in Phase 1):

| V2 sub-section | Effect | Direction | Severity |
| --- | --- | --- | --- |
| §3.2 Pledge as signal | Mechanism does not couple to pledge at all | Neutral | — |
| §4.1 Pot survival | Redistributes *within* each pool's pot; pot composition unchanged | Neutral | — |
| §4.2 Fee-gen population | Tx-submitter economics untouched | Neutral | — |
| §4.3 Price robustness | $\mu_{\min}$ is a ratio (price-robust). Paired `minPoolCost` reduction shrinks the absolute-ADA component | Mild positive (paired) | — |

**Amplification of existing V2 problems:**

| Existing problem | Amplification? | Note |
| --- | --- | --- |
| §3.1 structural floor (standalone) | No relief but no amplification either | Captured by Phase 2 contingency verdict |
| §3.4 behavioural concentration via race-to-zero-margin | **Relief** — race stopped by the floor | Positive unclaimed side effect |

**New problems outside V2:**

| New issue | Severity | Where it is addressed |
| --- | --- | --- |
| Governance overlap with CIP-0082 stage 2 — `minPoolRate` is mechanically identical to `minPoolMargin` | **Severe if both ship** | Deployment exclusivity in Phase 5 |
| Two-knob calibration coupling (`minPoolMargin` × `minPoolCost` in paired variant) | Moderate | Phase 5 mandates joint movement |
| Operator margin-anchoring — declared margins may drift *down* toward the floor from above | Low-moderate | Phase 5 KPI: declared-margin distribution |

**Composition with Phase 3.** No severe Phase 4 finding is unmitigated provided Phase 5 carries the exclusivity and joint-ramp constraints. A deployment path that ships CIP-0023 *and* CIP-0082 stage ≥ 2 independently fails Phase 4.

### 3.5 Phase 5 — Deployment contract

**Ramp and rollback:**

| Stage | Action | KPIs measured | Rollback trigger |
| --- | --- | --- | --- |
| Activation | `minPoolMargin = 0` at HFC | Baseline fee-rate dispersion; declared-margin distribution; sub-threshold pool count | N/A (calibration epoch) |
| Stage 1 | `minPoolMargin → 1 %` | Declared-margin distribution shift; delegator net-yield percentiles | Distribution unchanged *and* yield dispersion unchanged ⇒ instrument inactive, pause |
| Stage 2 | `minPoolMargin → 1.5 %` **paired with** `minPoolCost` reduction | As above + sub-threshold pool count, fee-rate Gini, delegator migration rate | Sub-threshold count rising; Gini not collapsing |
| Stage 3 (optional) | `minPoolMargin → 2 %` | As above + viable-independent SPO count | Viable-independent SPO count falling |

**Phase 4 mitigations encoded in the contract:**

- **Deployment exclusivity.** Governance must pick *either* CIP-0023 + companion `minPoolCost` reduction *or* CIP-0082 (stage ≥ 2 absorbs the margin-floor mechanism). Not both.
- **Mandatory pairing from Stage 2 onwards.** `minPoolMargin` and `minPoolCost` move together. Shipping margin-floor standalone is rejected by Phase 2 on §3.1.
- **Margin-anchoring watch.** Declared-margin distribution tracked per epoch; if mass concentrates on the floor from both sides (below and above), the floor is re-calibrated.

**Decision authority.** HFC-ratified parameter introduction; subsequent changes via standard `ParameterChange` with CC / SPO / dRep allocation per Conway-era rules.

## 4. Transition and governance

| Aspect | Path |
| --- | --- |
| On-chain path | Parameter update at HFC to introduce `minPoolMargin`; subsequent values via standard Parameter Change |
| Re-registration | None. Existing certificates with margin below the floor clamped inside ledger reward calc |
| Staging question | Governance decides whether `minPoolMargin` rise and `minPoolCost` drop move together or sequentially |
| Constitutional fit | Conway-era parameter extension; compatible with V2 §4.4 and the Cardano Constitution's parameter-change chapter |
| Acceptance per CIP | Initial-value agreement pre-HFC; PCP / TSC endorsement; SPO/dRep readiness; on-chain HFC ratification |

## 5. Interaction audit

### 5.1 Same-layer — CIP-0023 ↔ CIP-0082

CIP-0082 stage 2 removes `minPoolCost` and introduces `minPoolRate`, which is the **same margin-floor mechanism** CIP-0023 proposes. The CIP-0082 author explicitly credits CIP-0023 for the concept.

| Scenario | Outcome |
| --- | --- |
| CIP-0023 ships first | Stage 1 of CIP-0082 composes cleanly; stage 2 effectively renames and formalises `minPoolMargin` |
| CIP-0082 ships first | CIP-0023 is redundant past stage 2 |
| Both enacted as separate items | Incoherent — same instrument under two names |

**Conclusion.** CIP-0082 functionally absorbs CIP-0023.

### 5.2 Cross-layer — CIP-0023 ↔ CIP-0050 / CIP-0037

The stake-cap candidates (CIP-0050, CIP-0037) modify $\sigma^{\text{eligible}}$ *before* the reward curve; CIP-0023 applies *after* the curve. Composition is clean — sequentially ordered by construction, no precedence rule required.

### 5.3 Dependency chain

- Margin-floor-only reform leaves §3.2 untouched (pledge stays economically inert).
- Margin-floor-only reform leaves custodial-operator concentration (CEX / IVaaS) unaddressed — entity-level accounting is beyond the fee layer.
- A full V2-aligned package pairs CIP-0023 (or its successor CIP-0082 stage ≥ 2) with a stake-cap reform.

## 6. Gaps against V2

| Gap | Why |
| --- | --- |
| §3.2 direct | No pledge-layer response |
| §3.4 structural | No entity-level accounting; behavioural only |
| §4.1, §4.2 | Fee-layer change does not touch pot composition or fee-generating population |
| Standalone §3.1 | Marginal without a companion `minPoolCost` reduction |

**Role in a V2 package.** *Necessary but not sufficient.* Primary historical role: identified the margin-floor instrument that CIP-0082 later operationalises within a staged path.
