# CIP-0082 — Improved Rewards Scheme Parameters (4-stage)

> **Status:** Active 2026/04/22. Fee-layer candidate (stages 1–2) + transversal `k` reform (stages 3–4). Evaluation against V2 §2 grid. Sources in §7.

## TL;DR

- **Verdict.** Broadest candidate in the bundle. **Most natural opening move** of a V2-aligned package: stage 1 + stage 2 clear §3.1 and §3.3 in one coordinated path.
- **Staging strength.** Four separate on-chain actions (3 parameter updates + 1 hard fork) with built-in review boundaries. Aligns directly with V2 §4.4.
- **Known gaps.** §3.2 (pledge as direct signal) only *indirectly* addressed; §3.4 only through `k`-driven fragmentation. A stake-cap-layer pairing (CIP-0050 or CIP-0037) remains necessary.
- **Stage-2 empirical risk.** Flat yields make brand/convenience the dominant delegator signal — stage 2 may neutralise fee regressivity without redistributing delegation.

## 1. Mechanism

### 1.1 Four stages

| Stage | Action | Technical path | Parameter |
| :---: | --- | --- | --- |
| 1 | Halve `minPoolCost` | Parameter update | `minPoolCost = 170` ADA |
| 2 | Remove `minPoolCost`; introduce `minPoolRate` | **Hard fork** + ledger-rule change | `minPoolRate = 0.03` (3 %) |
| 3 | Raise `k` | Parameter update | `stakePoolTargetNum = 750` |
| 4 | Raise `k` again | Parameter update | `stakePoolTargetNum = 1000` |

Proposed interval between stages: 3 epochs (≈ 15 days).

### 1.2 Fee-layer mechanics at stage 2

$$poolRateEff = \max(poolRate,\ minPoolRate)$$

`minPoolCost` is removed entirely. Operator compensation shifts from fixed-per-pool ADA to a proportional margin floor. Existing certificates remain valid (backwards-compat mirrors CIP-0023).

### 1.3 Author's headline — viability/competitive point collapse (epoch 385 ref.)

| State | Viability point | Competitive point |
| --- | ---: | ---: |
| Current | ~670 000 ADA | ~20 000 000 ADA |
| Post-stage 1 | ~335 000 ADA | ~16 500 000 ADA |
| Post-stage 2 | 1 ADA | 1 ADA |
| Post-stages 3–4 | 1 ADA | 1 ADA |

- *Viability point:* pledge needed for a zero-delegation pool to distribute nonzero rewards.
- *Competitive point:* pledge needed for a zero-delegation pool to match a saturated zero-pledge pool's delegator yield.

Both collapse to 1 ADA at stage 2 because removing `minPoolCost` eliminates the per-pool fixed cost that currently dominates small-pool economics.

### 1.4 Delegator yield at stage 2 — near-flat across pool size

| Pool type | Stake | Pledge | Delegator ROS |
| --- | --- | --- | ---: |
| Sybil | 100 k ADA | 100 k | 3.6615 % |
| Sybil | 1 M ADA | 1 M | 3.6617 % |
| Community | 10 M ADA | 100 k | 3.6631 % |
| Community | Saturated | 1 M | 3.6773 % |

Dispersion = **0.0158 pp** — essentially flat. Stage 2 levels the yield playing field; the residual differentiator is the pledge benefit via $a_0 = 0.3$.

## 2. Milestone coverage

| V2 milestone | Verdict | Where it bites |
| --- | --- | --- |
| §3.1 Operator viability | **Direct, strong** | Stage 1 halves `minPoolCost` → stage 2 eliminates it; viability floor collapses |
| §3.2 Pledge as signal | Indirect | $a_0$ and pledge curve untouched; higher `k` amplifies the existing pledge benefit |
| §3.3 Delegator yield | **Direct** | `minPoolRate` bounds operator take; fixed-fee removal passes relief to small-pool delegators |
| §3.4 Concentration | Partial, indirect | Stages 3–4 fragment saturation; no entity-level accounting |
| §4.1 Pot survival | No effect | Redistribution within the existing pot |
| §4.2 Fee-gen population | Out of scope | — |
| §4.3 Price robustness | **Improved** | `minPoolRate` (proportional) removes the hard ADA-price dependency that `minPoolCost` imposes |
| §4.4 Governability | **Strong** | Explicit staging; each stage is a separate on-chain action |

**Dependency-chain verdict.** CIP-0082 secures §3.1 at stage 1, clears §3.1 + §3.3 at stage 2, applies pressure on §3.4 at stages 3–4. §3.2 stays indirect — a stake-cap pairing remains necessary.

## 3. Validation plan

Gated per [`../methodology.md`](../methodology.md). G1 and G2 are strong on §3.1 and §3.3; G4 carries the load for §3.4, and is precisely where the instrument's residual risk lives.

### 3.1 G1 — Analytical properties

| Property | Claim | Status |
| --- | --- | --- |
| Viability collapse at stage 2 | Removing `minPoolCost` drops both viability and competitive points to 1 ADA | Theorem (CIP §1.3 worked example) |
| Near-flat delegator ROS at stage 2 | Across pool sizes with pledge variation, ROS dispersion ≈ 0.0158 pp | Algebraic — see CIP §1.4 table |
| `minPoolRate` clamp | $poolRateEff = \max(poolRate, minPoolRate)$ — monotone in rate floor | Theorem |
| Hard-fork requirement at stage 2 | Rule change, not scalar update | Structural |
| Staging preserves backward compat | Existing certificates clamped inside ledger reward calc | Design invariant |
| Governance surface | Four stages (3 parameter updates + 1 HFC) | Direct count |

### 3.2 G2 — Mainnet-snapshot counterfactual

Stage-by-stage application against a recent epoch (V2 anchor epoch 623 — author's worked example uses epoch 385):

| Stage | Population | Immediate effect |
| --- | --- | --- |
| 1: `minPoolCost = 170` | 116 sub-threshold pools | Halved fixed-fee burden; some re-enter viability |
| 1: `minPoolCost = 170` | 283 viable independent | Margin uplift at small stake |
| **2**: `minPoolCost` removed + `minPoolRate = 3 %` | All viability tiers | Viability / competitive points → 1 ADA |
| **2** | Reference delegator | ROS dispersion: **22.7 → 0.7 %** range collapses to **≈ 0.02 pp** |
| **2** | 85 MPO fleet entities (901 pools) | Flat delegator ROS → fee regressivity neutralised |
| **2** | 10 CEX / IVaaS (181 pools, 7.40 B ADA) | Fee advantage flattened — but fleet count unconstrained |
| 3: `k = 750` | All pools | Per-pool saturation target drops — see [`../k-parameter.md`](../k-parameter.md) |
| 4: `k = 1 000` | All pools | Further saturation compression |

**G2 verdict.** Stages 1–2 clear §3.1 and §3.3 by arithmetic. Stages 3–4 rely on a G4 MPO-response assumption for §3.4 — G2 alone does not establish §3.4.

### 3.3 G3 — Historical analogies

| Anchor | Relevance | Caveat |
| --- | --- | --- |
| `k: 150 → 500` (2020) | Caution for stages 3–4: weak-pledge `k` raise elicits MPO fleet expansion | Single observation |
| No prior `minPoolCost` removal | — | Stage 2 has no direct historical analogue; closest analogue is fee-schedule updates 2020–2021 |
| Brand-driven CEX delegation (continuous) | Supports the G4 concern that flat yield ⇒ brand differentiator dominates | Persistent pattern, not an event |

### 3.4 G4 — Population best-response reasoning

*Assumptions, not predictions.* The critical §3.4 uncertainty is here.

| Population | Pre-stage-2 | Stage-2 best response | Threatens |
| --- | --- | --- | --- |
| Sub-threshold pool operator | Below viability | Re-enter viable band | — (intended) |
| Viable independent single-pool | Margin squeezed by fixed fee | Retain stake; small uplift | — (intended) |
| MPO fleet under flat yield | Extract via per-pool fixed fee | Brand + convenience become dominant differentiator — **fleet may consolidate *or* grow, depending on brand pull** | **§3.4 direct** |
| CEX / IVaaS | Native pledge + brand + fee advantage | Fee advantage flattened; brand + convenience remain | **§3.4 direct** — stages 3–4 alone may not constrain |
| Delegator | Chases ROS differential | ROS differential flattens → chases brand, familiarity, UX | **§3.4 amplifies** under flat yield |

**Critical G4 question.** Under stage 2 + stage 3 joint activation, flat-yield competition with zero fixed fee makes brand and convenience the dominant differentiators — the same factors diagnostic §1.2.4.3.5 identifies as concentration-reinforcing. **Stage 2 may neutralise fee regressivity without redistributing delegation.** Without a stake-cap pairing, this risk lands directly on §3.4.

### 3.5 G5 — Governance ramp and rollback

The CIP already specifies a 4-stage path. G5 layer adds measurement and rollback triggers:

| Stage | Action | What to measure | Rollback trigger |
| --- | --- | --- | --- |
| 1 | `minPoolCost: 340 → 170` | Subthreshold count, declared-margin distribution | Subthreshold count not shrinking after 6 epochs |
| 2 | HFC: `minPoolCost` removed + `minPoolRate = 3 %` | ROS dispersion, margin distribution, entity-level HHI | Entity HHI rising ⇒ pause before stage 3 |
| 3 | `k: 500 → 750` | MAV / Nakamoto trajectory, MPO fleet size, subthreshold count | MAV trending **down** or MPO fleet size **rising** |
| 4 | `k: 750 → 1 000` | As above | Same triggers as stage 3 |

**Interval.** The CIP proposes 3 epochs (~15 days) between stages. G5 recommends **5–10 epochs (25–50 days)** to allow delegation response and MPO coordination to surface before the next lever fires.

**Stage-3 precondition.** Recommended: do not advance to stage 3 until the stake-cap layer is active (CIP-0050 or CIP-0037). Without it, stage 3 is a weak-pledge `k` raise — the exact G3 historical anti-pattern.

### 3.6 G6 — Exploratory simulation (optional)

## 4. Transition and governance

| Aspect | Path / Risk |
| --- | --- |
| Staging | 4 separate on-chain actions (3 parameter updates + 1 hard fork at stage 2). Observation between stages is load-bearing. |
| Stage-2 ordering risk | Removing `minPoolCost` without simultaneously installing `minPoolRate` would collapse compensation onto a margin layer driven toward zero. The CIP correctly couples them into one hard fork — this ordering must be preserved. |
| Backwards compatibility | `poolRateEff = max(poolRate, minPoolRate)` mirrors the CIP-0023 clamping mechanism. No re-registration. |
| 3-epoch interval | Proposed 15 days may be too short for delegation response and MPO coordination. Simulation should test 5–10 epochs (25–50 days) as alternatives. |
| Stage-3 / stage-4 risk | `k` raise 500 → 750 → 1000 with fee-layer relief in place is *argued* to pressure MPO consolidation — not empirically established. Standalone treatment in [`../k-parameter.md`](../k-parameter.md). |

## 5. Interaction audit

### 5.1 Same-layer — CIP-0082 ↔ CIP-0023

CIP-0082 explicitly supersedes CIP-0023. The author notes `minPoolRate` was "originally proposed in CIP-0023" and adopts the mechanism as stage 2 of a larger package. **Pick one path**: CIP-0082's staged plan, or CIP-0023 alone (without the subsequent `minPoolCost` removal and `k` increases).

### 5.2 Cross-layer pairings

| Pairing | Profile |
| --- | --- |
| **CIP-0082 + CIP-0050** | **House recommendation.** Viability-first + leverage cap prevents race-to-zero-pledge under flat yields. |
| **CIP-0082 + CIP-0037** | Strongest on §3.2 (direct pledge-capacity coupling) + §3.4 (`k` + pledge-linked saturation compound). More instrument complexity. |
| **CIP-0082 alone** | §3.2 indirect only; §3.4 only via `k` fragmentation. Risks concentrated flat-yield pools dominated by brand and convenience. |

### 5.3 `k` interaction with stake-cap pairings

- **With CIP-0050.** At `L = 100` and `k = 1 000`, a pool needs pledge ≥ 1 % of `1/k = 0.1 %` of total stake to use full saturation. The binding constraint at the marginal MPO pool depends on whether `L·pledge < 1/k`.
- **With CIP-0037.** Effects compound because saturation itself is pledge-indexed; joint recalibration of `(e, ℓ, p_{100\%})` required at each `k` raise.

### 5.4 Dependency-chain ordering

CIP-0082 covers §3.1 at stages 1–2 *before* raising `k` at stages 3–4 — respects V2 ordering. Raising `k` outside this package (as a standalone parameter update) is flagged by V2 §5 as *building on a foundation that does not exist*; the `k` raise is only safe once the viability floor is cleared.

### 5.5 What CIP-0082 does not cover

| Gap | Effect |
| --- | --- |
| Pledge as direct economic signal | $a_0$ and pledge-bonus curve untouched; 95.6 % of pledge-bonus budget still unused. Requires stake-cap pairing. |
| Custodial constraint | 10 CEX/IVaaS entities (181 pools, 7.40 B ADA) continue unconstrained. |
| §4.1 pot survival | No instrument. |
| §4.2 fee-gen population | No instrument. |

## 6. Gaps against V2

**Role in a V2 package.** Foundation instrument. Necessary, and in its staged form *sufficient* for §3.1 + §3.3. Not sufficient for §3.2, §3.4, §4.1, §4.2.
